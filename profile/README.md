<p>"这条 IP 不干净"是一句结论，不是一个指标。真要判断干不干净，得把它拆成四个能读出数字的量：归属主体、类型标签、滥用记录、同段复用。四项各有各的查询入口和判断阈值，凑齐之后才谈得上处置。这篇按说明书的方式写——每个指标给出查法、正常读数范围和超标后的动作，遇到问题可以对着条目逐项核。</p>

<h2>一、先把不干净翻译成四个可测的量</h2>
<p>很多人拿到一条地址，只查一个归属地就下单了。归属地只回答"这条地址注册在哪个国家"，完全不涉及它被谁用过、现在是否被标记。真正决定可用性的是后面三项。</p>
<h3>四个指标分别回答什么问题</h3>
<p>ASN 与注册主体回答"它挂在谁名下"；类型标签回答"情报库认为它是什么"；滥用记录回答"最近有没有人投诉它"；复用率回答"现在有多少人和你共用它"。四项独立，缺一项判断就会偏。</p>
<h3>指标之间会互相矛盾</h3>
<p>常见情形是 ASN 属于住宅运营商，但类型库标成托管。这种矛盾通常来自地址被转租过。遇到矛盾时按更严格的一侧处理，宁可放弃也不要赌。</p>

<h2>二、ASN 与注册主体：一条 whois 能看出大半</h2>
<p>这是成本最低、信息量最大的一步。命令行的 whois 或者任意 IP 查询站都能给出结果，重点看三个字段：ASN 编号、AS 名称、netname。</p>

<h3>看 AS 名称里有没有 IDC、Cloud、Hosting 这类词</h3>
<p>住宅运营商的 AS 名称通常带 Telecom、Broadband、Cable、Fiber 之类的词；机房类常见 Hosting、Cloud、Server、Datacenter。名称可以伪装，但 ASN 编号与 BGP 公告改不了，配合 bgp.he.net 查公告前缀更可靠。</p>
<h3>看前缀长度和邻居数量</h3>
<p>一条 /24 里如果只有极少数地址被公告，或者同一 AS 下公告了大量互不相关的 /24，都值得警惕。前者可能是临时租用，后者常见于批量转售的地址池。</p>

<h2>三、滥用记录：查哪个库、看哪个时间窗</h2>
<p>滥用记录是四项里最容易被供应商含糊带过的一项。公开库不少，但各自的样本来源不同，结论经常不一致，所以要看两到三个库并交叉比对。</p>
<h3>三个常用入口</h3>
<p>Spamhaus 看是否在封锁列表内，AbuseIPDB 看近九十天的举报数量与类别，IPQualityScore 一类服务给出综合风险分。前两个免费可查，第三个通常有免费额度。</p>
<h3>时间窗比总数更重要</h3>
<p>三年前有五十条投诉、最近九十天为零，和最近一周有五条投诉，性质完全不同。判断时以最近九十天为主，最近三十天的权重最高。老记录会随时间衰减，新记录不会。</p>
<h3>投诉类别也要看</h3>
<p>垃圾邮件类投诉对网页登录影响有限，批量注册、撞库、爬虫类投诉影响直接。同样是十条记录，类别不同，结论可能相反。</p>

<h2>四、共享复用率：供应商不给数字时怎么估</h2>
<p>复用率是最不透明的一项，因为它直接影响供应商的毛利，很少有服务商会主动披露。拿不到准确数字时，可以用几个间接方法估个大概。</p>
<h3>方法一：看延迟与路由的稳定性</h3>
<p>同一地址在不同时段的 traceroute 路径如果频繁变化，说明上游在做负载调度，背后很可能挂着多条会话。路径稳定、跳数固定，至少说明这条地址是固定分配的。</p>
<h3>方法二：看并发表现</h3>
<p>自己在同一地址上开两三个长连接，观察是否出现互相挤占、超时增加。共享地址在高峰时段的表现会明显劣化，独享地址则相对平稳。</p>
<h3>方法三：直接问，看回答方式</h3>
<p>问"这个段已售出多少条、单地址允许几个并发"，愿意给具体数字的供应商通常管理规范；回答"我们都是独享"却说不清并发上限的，基本可以判定为共享池包装。</p>

<h2>五、四项指标的读数对照与处置动作</h2>
<p>四项查完会得到一组读数。下面按常见组合给出处置建议，注意这里的动作是递进的：能修的先修，修不了再换。</p>
<h3>只有一项轻微超标：先观察，不必急着换</h3>
<p>比如滥用记录有一条三个月前的投诉、类型标签在两个库里一致。这种情况先跑一周实际使用，看验证频率是否正常。指标是概率，不是判决。</p>
<h3>两项以上超标：直接换，不要修</h3>
<p>地址本身的问题无法在客户端修复。此时继续调参数、换浏览器都是浪费，直接申请替换，并把四项读数作为替换依据提交给供应商，通常能加快处理。</p>

<h2>六、换 IP 之前先做的两步确认</h2>
<p>下定决心换之前，还有两件事值得花十分钟确认，它们能避免你把环境问题误判成地址问题。</p>
<h3>第一步：用同一账号换一条已知干净的出口做对照</h3>
<p>如果现象消失，确认是地址问题；如果现象依旧，问题在设备或账号，换 IP 没有意义。这一步能省下一次不必要的替换流程。</p>
<h3>第二步：确认新地址的四项读数</h3>
<p>替换不是换一个就行，新地址同样要过一遍四项检查。很多人换了之后问题依旧，是因为换来的还是同一批转售地址，只是编号不同。</p>

<h2>常见问答</h2>
<h3>IP 查询站显示是住宅，就一定是干净的吗？</h3>
<p>答：不一定。归属类型只说明它挂在住宅运营商名下，不代表没有滥用历史。要把滥用记录和复用率一起看，三项都过才算可用。</p>
<h3>AbuseIPDB 上有一条报告要紧吗？</h3>
<p>答：看时间和类别。三个月前的一条垃圾邮件类报告影响很小；一周内的批量注册类报告就值得警惕。报告数量不如报告的新鲜度和类别重要。</p>
<h3>怎么判断供应商给的是不是共享池？</h3>
<p>答：问三个问题：同段已售多少条、单地址并发上限几个、能否提供 ASN 与 netname。三个都答得具体的可信度高，回避并发上限的基本是共享。</p>
<h3>地址刚买来干净，用一段时间变脏了怎么办？</h3>
<p>答：这在共享地址上很常见，因为邻居的行为会影响整个地址。处置方式是换到独享地址，并保留每次检查的记录，作为向供应商申请替换的依据。</p>
